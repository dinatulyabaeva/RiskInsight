# SPEC — RiskInsight v1.0

## Цель и границы

Создать учебный end-to-end сервис исследования качества кредитного портфеля. Пользователь задает вопрос через Web, LLM выбирает аналитические инструменты MCP, система рассчитывает показатели на синтетической базе и возвращает проверяемый ответ.

Не цели MVP: индивидуальные кредитные решения; скоринг людей; реальная банковская интеграция; прогноз NPL; регуляторный расчет резервов; загрузка произвольных CSV/SQL; multi-tenant production; отправка отчетов третьим лицам.

## Роли и сценарии

Основная роль — риск-аналитик. Администратор задает конфигурацию LLM, общий access token и публикует сервис. Данные общие, синтетические; отдельных пользовательских портфелей нет.

US-01. Аналитик открывает дашборд и видит срез, объем, DPD90+, число кредитов и учебный EL.
US-02. Аналитик выбирает продукт/регион/рейтинг; все графики отражают ту же область.
US-03. Аналитик спрашивает о динамике; LLM выбирает доступные даты, получает результаты MCP и формулирует выводы.
US-04. Аналитик спрашивает о причинах роста; агент использует математическое разложение и не выдает его за причинное доказательство.
US-05. Аналитик выполняет what-if по PD/LGD; результат явно не называется прогнозом.
US-06. Аналитик открывает [Tn], проверяет параметры и результаты, экспортирует отчет и журнал.
US-07. При неверном ключе или недоступном API аналитик видит ошибку; DEMO не подменяет LLM.
US-08. Проверяющий запускает приложение, тесты, презентацию и демонстрирует настоящий MCP.

## Контракты данных

`loans`: loan_id, product, region, risk_band, annual_rate, origination_date, original_principal_kop.
`snapshots`: (as_of, loan_id) PK; balance_kop>0, dpd>=0, pd_12m∈[0,1], lgd∈[0,1].
`metadata`: dataset_version, seed, n_loans, даты, валюта и флаг synthetic.

Деньги хранятся в целых копейках; преобразование в RUB происходит на выходе. Доли считаются по остатку, count-based NPL — отдельное поле. Все метрики одной сводки относятся к одной дате. Нельзя суммировать остатки разных дат.

Данные — закрытая фиксированная когорта: 4 продукта, 5 условных регионов, рейтинги A–D. Нет новых выдач, списаний, платежного календаря и реальных значений PD/LGD. Подробности: `docs/DATA_DICTIONARY.md`.

## Контракты API и MCP

API: GET /api/health, /api/ready, /api/context, /api/dashboard, /api/methodology; POST /api/chat.
Chat input: question (3..2500 символов), scenario? (для DEMO), as_of?, filters {product?,region?,risk_band?}. Extra fields запрещены.
Chat output: request_id, mode, answer, trace[], protocol{}, usage{}, warnings[], duration_ms, scope.

MCP: JSON-RPC 2.0, UTF-8, одна JSON-запись на строку, транспорт stdio. Supported version 2025-06-18; capabilities tools/resources. Схемы получаются из Pydantic, каталог содержит 9 инструментов. Успешный результат содержит content + structuredContent; ошибки инструмента isError=true; ошибки протокола JSON-RPC error. Сервер не рекламирует неподдерживаемые capabilities.

## AI-агент

LLM endpoint задается только серверной конфигурацией. Инструменты собираются из MCP tools/list; arbitrary tool names не разрешены. Первый раунд требует tool call. Системный prompt задает область, методологию, ссылки и ограничения. Модель выбирает последовательность; расчет метрик остается детерминированным.

Бюджет по умолчанию: до 5 tool-rounds и 1 final round, максимум 10 выполняемых вызовов, 4096 max_completion_tokens на запрос, 60 секунд на LLM request. Это верхние технические ограничения, не гарантия качества или цены. При исчерпании бюджета требуется итог без новых инструментов. При отсутствии успешных MCP-вызовов неподтвержденный финальный ответ отклоняется.

Данные и ответы инструментов считаются недоверенным содержимым. Секреты не входят в prompt и не передаются MCP child process. Проверка [Tn] проверяет существование, не семантическую истинность всех утверждений.

DEMO — отдельный путь без LLM, выполняющий явно выбранный фиксированный сценарий через настоящий MCP. Он нужен для настройки и воспроизводимой проверки, не для закрытия AI-критерия.

## Нефункциональные требования

NFR-01. Python 3.11+, простой локальный запуск без Node/CDN.
NFR-02. Нельзя исполнять пользовательские SQL, shell или Python.
NFR-03. Read-only запросы, parameter binding, allowlist группировок.
NFR-04. Серверные secrets, shared access token, глобальный лимит 12 chat-запросов/минуту, semaphore 2.
NFR-05. Один Uvicorn worker; распределенная квота не реализована. Дашборд ограничивается concurrency, но не минутной LLM-квотой.
NFR-06. Приложение не является high-availability банковским сервисом; SSO, audit retention, DLP, WAF и независимая валидация модели вне MVP.
NFR-07. Все ответы синтетические и не должны использоваться для решений о реальных клиентах.

## Definition of Done

Для **кода MVP**: тесты проходят; API получает цифры через MCP; интерфейс и презентация открываются; README описывает ограничения и запуск. Выполнено в поставке с деталями в TEST_REPORT.

Для **сдачи проекта по заданию** дополнительно: реальная модель доступна и проверена; независимый MCP-клиент проверен; публичный репозиторий и HTTPS-сервис опубликованы; реальные ссылки добавлены в README; студент прошел обязательный воркшоп и подготовил живую демонстрацию. Эти внешние действия не выдаются за уже выполненные.

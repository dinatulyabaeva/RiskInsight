# Архитектурные решения (ADR)

## ADR-001 — FastAPI + небольшой статический UI
Решение: отделить API от интерфейса, не требовать Node-сборки. Причина: явная демонстрация сквозного сценария, тестируемость и единый Docker-контейнер. Цена: ручная реализация DOM/графиков вместо готовых компонентов Streamlit.

## ADR-002 — Python/SQL считает, LLM выбирает и объясняет
Решение: метрики и декомпозиция детерминированы; модель получает агрегированные результаты tools. Причина: воспроизводимость чисел. Цена: все разрешенные виды анализа нужно реализовать заранее; свободный SQL и произвольный код запрещены.

## ADR-003 — Настоящий MCP stdio, небольшой wire implementation
Решение: tools/resources subset protocol 2025-06-18, отдельный процесс, настоящий handshake и вызовы. Причина: самодостаточная проверка в среде без возможности установить SDK и простая локальная инфраструктура. Цена: часть протокола поддерживается явно, не весь MCP. Требуются независимый sdk_smoke/Inspector и дальнейшая поддержка совместимости. Для remote deployment предпочтительнее отдельная миграция на официальный SDK, а не расширение самописного HTTP-транспорта.

## ADR-004 — Одна SQLite-база, неизменяемая синтетическая панель
Решение: фиксированный seed, нет пользовательской загрузки файлов. Причина: воспроизводимость и отсутствие реальных клиентских данных. Цена: упрощенный процесс кредитования, не валидированный risk model и нет multi-user data isolation.

## ADR-005 — DEMO не называется AI
Решение: отдельные сценарии и явная метка режима. Причина: приложение можно проверить без API key, не вводя проверяющего в заблуждение. Цена: для выполнения LLM-критерия ключ и live smoke обязательны.

## ADR-006 — Источники вместо скрытых рассуждений
Решение: показывать инструмент, параметры, результат и source_ref, а не chain of thought. Причина: проверка фактов и воспроизводимость действий. Цена: ссылка на существующий tool не доказывает, что все выводы модели корректны; нужен human review.

## ADR-007 — Упрощенная публикация, но без вымышленных статусов
Решение: Docker, Compose, Blueprint и инструкции; не писать URL до реального деплоя. Причина: внешние аккаунты и секреты принадлежат пользователю, платные ресурсы не создаются без его подключения/подтверждения.

# Данные и методология

## Происхождение

Генератор `app/db.py`, `random.Random(42)`, версия `synthetic-v1-seed42`. 10 000 кредитов, 12 месячных срезов (октябрь 2025 — сентябрь 2026). Всего 120 000 наблюдений. База создается атомарной заменой готового файла. При существующей БД bootstrap проверяет версию и не перезаписывает ее.

У всех кредитов условная дата выдачи до начала окна. Когорта фиксирована: нет новых выдач, закрытий и списаний. Баланс амортизируется с условной скоростью по продукту; при просрочке амортизация меньше. DPD изменяется по простому стохастическому процессу с ростом и возможным возвратом к нулю. Это не платежный календарь и не реалистичный бухгалтерский ledger.

Начиная с апреля 2026 генератор повышает интенсивность условного ухудшения для потребительского продукта и Приволжского сегмента. Это искусственно заданный механизм для учебного анализа, не оценка реальных регионов. Даже при заложенном ухудшении наибольший вклад в агрегированный риск может иметь большой, но менее рискованный сегмент.

## Таблица loans

| Поле | Тип | Смысл |
|---|---|---|
| loan_id | TEXT PK | Вымышленный идентификатор SYN-000001; не клиент |
| product | TEXT | Потребительский, Автокредит, Ипотека, Кредитная карта |
| region | TEXT | Пять условных региональных категорий |

| annual_rate | REAL | Условная годовая ставка, доля 0..1 |
| origination_date | TEXT | ISO дата до первого среза |
| original_principal_kop | INTEGER | Первоначальная сумма, целые копейки |

## Таблица snapshots

| Поле | Тип | Смысл |
|---|---|---|
| as_of | TEXT PK-part | Дата конца месяца |
| loan_id | TEXT PK-part, FK | Связь с loans |
| balance_kop | INTEGER >0 | Остаток основного долга, копейки |
| dpd | INTEGER >=0 | Число условных дней просрочки |
| pd_12m | REAL 0..1 | Синтетическая 12-месячная PD; для DPD>=90 задается 1 |
| lgd | REAL 0..1 | Синтетическая LGD по продукту |

В API balance_rub, npl90_balance_rub, el_rub выражены в рублях. KPI показывают млн/млрд с округлением. Исходные результаты tools доступны для проверки.

## Метрики

`NPL90 proxy = Σ balance_kop(DPD>=90) / Σ balance_kop`.
`NPL90 count ratio = count(DPD>=90) / count(loans)` — отдельная count-based метрика, не используется вместо balance-based в KPI.
`weighted_rate = Σ(balance × annual_rate) / Σ(balance)`.
`EL12 = Σ(balance × pd_12m × lgd)`; PD/LGD не калиброваны, не прогноз и не IFRS 9 ECL.
`DPD buckets`: 0; 1–29; 30–59; 60–89; >=90, без пересечений.
`delta_pp = (ratio_end − ratio_start) ×100`.

Для `explain_npl_change` используется симметричное разложение, точное до округления результатов:

```text
R(t) = Σ w(segment,t) × r(segment,t)
ΔR = Σ [ (w0+w1)/2 × (r1-r0) + (r0+r1)/2 × (w1-w0) ]
```

Первое слагаемое — вклад изменения внутренней доли просрочки, второе — структуры. Это не оценка причин и не регрессия. Промежуточные доли не округляются; итоговые вклады выдаются с 6 знаками в п.п.

## Контроль качества

PRIMARY KEY запрещает дубликаты loan/date. CHECK задает диапазоны. `check_data_quality` проверяет допустимость значений, потерянные связи, quick_check SQLite и размер панели. Это не проверка полноты каждого возможного источника данных или адекватности модели риска.

## Обновление данных

```bash
python -m scripts.seed --loans 10000 --force
```

`--force` заменяет существующий файл учебной БД. Не использовать для реальных данных. После изменения генератора обновите презентацию и контрольные скриншоты. Установка `SEED_LOANS` не изменит уже существующую базу: пересоздайте ее явно.

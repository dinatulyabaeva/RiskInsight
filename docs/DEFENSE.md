# Защита: сценарий на 9–10 минут

## До демонстрации

Публичный репозиторий и сервис должны существовать и открываться из обычного браузера. Заполните реальные ссылки в README. Настройте LLM-режим, используйте небольшую платную квоту/доступную локальную модель. Выполните pytest, live check_llm, внешний sdk_smoke, HTTP smoke и тест хостинга. Проверьте токен приложения, не показывая ключ модели на экране. Пройдите обязательный воркшоп и согласование темы отдельно.

Скриншоты в поставке относятся к DEMO. Их нельзя представлять как доказательство успешного LLM-вызова. Свежий скриншот live режима сделайте после настройки своей модели.

## Живой сценарий

Откройте приложение. Покажите метку LLM, синтетические данные, дату 2026-09-30, общий портфель. Не называйте дату текущей.

Введите: «Проанализируй качество портфеля за последние шесть доступных срезов. Какие продукты дали вклад в изменение DPD 90+? Отдели факты от гипотез, укажи даты и источники».

Откройте trace: get_dataset_context, доступные даты, get_npl_trend, explain_npl_change (порядок и состав зависят от модели). Покажите отдельный JSON-RPC handshake. Нажмите [Tn], сравните итог с фактическими результатами. Объясните, почему большой сегмент может дать большой вклад при умеренной доле риска.

Смените продукт и задайте самодостаточный вопрос. Покажите, что фактические фильтры сохранены в источниках. Выполните стресс-сценарий и назовите его what-if. Экспортируйте Markdown и журнал.

Если LLM недоступна, покажите явную ошибку. Затем отдельно продемонстрируйте DEMO, проговорив, что это запасной сценарий инфраструктуры, не исполнение AI-требования. Не заявляйте успешную работу модели при ее отсутствии.

## Вероятные вопросы

**Где MCP, а не просто tool calling?** LLM выдает tool_calls, оркестратор передает их отдельному процессу по MCP stdio. Есть initialize, capability negotiation, tools/list, tools/call, resource. Tool calling модели и MCP — разные слои.

**Почему допустим stdio в hosted Web-сервисе?** Публичным является Web API; MCP-сервер запускается внутри того же контейнера. Межпроцессный stdio не требует отдельного внешнего порта. Для независимого remote MCP нужен иной транспорт и auth.

**В чем основная роль AI?** Выбор последовательности анализа по вопросу и интерпретация результатов; числа не вычисляются LLM. В DEMO этой роли нет, что явно показано.

**Как исключены галлюцинации?** Они не исключены полностью. Числа доступны из инструментов, есть источник и allowlist, но интерпретации могут быть ошибочны. Система помогает проверке, а не заменяет аналитика.

**Почему нельзя назвать разложение ответом «почему»?** Это арифметическая атрибуция. Для причин нужны дополнительные данные и дизайн причинного анализа.

**Почему NPL — proxy?** В коде критерий только DPD>=90. Более широкие регуляторные определения в проект не включены.

**Что проверено на самом деле?** 66 локальных тестов, реальный MCP, реальный HTTP API, UI в браузерном harness. LLM provider в автотесте — mock; live ключ, Docker, внешняя MCP-совместимость и публичный хостинг проверяются владельцем перед защитой.

**Что бы улучшили дальше?** Семантические LLM-evals, числовая проверка утверждений, проверенный SDK-клиент, удаленный MCP при необходимости, роли/аудит, защищенная интеграция реальных данных. Не расширять MVP до автоматических кредитных решений без отдельной валидации.

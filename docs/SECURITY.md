# Безопасность и ограничения эксплуатации

## Реализовано

Секреты читаются только сервером из env/.env. .env исключен из Git и Docker build context. MCP child process не наследует LLM_API_KEY и APP_ACCESS_TOKEN. Пользователь не может менять LLM_BASE_URL через API. Для внешнего URL разрешен HTTPS; HTTP ограничен локальными именами.

Все инструменты read-only; SQLite открывается в mode=ro с query_only. Значения SQL параметризованы, группировки из allowlist. Произвольный SQL, shell, Python, доступ к файлам и внешним URL не входят в каталог MCP. Неизвестные инструменты LLM не исполняются.

Pydantic запрещает лишние поля и ограничивает даты, длины, enum, лимиты и коэффициенты. В запросе чата ограничены длина вопроса, число раундов, число инструментов и время. Глобальная минутная квота действует на chat, semaphore — на MCP-запросы. Токен проверяется constant-time сравнением.

LLM текст отображается через textContent/text nodes. Ответ не исполняется как HTML. Токен приложения хранится только в памяти текущей вкладки. Есть nosniff, no-referrer, frame-ancestors DENY и no-store для API. CSP допускает inline JS/CSS ради standalone-презентации; это компромисс, не максимальная CSP-защита.

Штатные provider errors не включают upstream body или ключ. Application log не сохраняет текст вопроса, tool results или токены. Встроенный trace доступен тому, кто имеет access token; это общий учебный портфель.

## Не реализовано / нельзя обещать

SSO, полноценный IAM, отдельные пользователи и роли, tenant isolation, row-level security, persistent audit, шифрование локальной БД, ротация ключей, DLP, WAF, распределенные quotas и гарантия защиты от prompt injection вне catalog allowlist отсутствуют. Обнаружение всех ложных утверждений LLM не реализовано.

Глобальный limiter находится в памяти одного процесса; перезапуск сбрасывает счетчик, несколько workers/реплик создают независимые лимиты. Используйте один worker в MVP. Для production требуется внешний gateway/Redis и реальные аккаунты. Запросы дашборда имеют concurrency limit, но не отдельную rate limit — публичное read-only API тоже требует инфраструктурной защиты.

Ограничение Content-Length в приложении не заменяет лимит тела запроса на reverse proxy; для production нужен лимит и на chunked bodies. Не используйте этот MVP как публичный paid-LLM proxy без токена и upstream бюджета.

## Перед публичным LLM-режимом

Задайте длинный случайный APP_ACCESS_TOKEN. Включите бюджет и лимиты у LLM-провайдера. Не публикуйте ключ в issue, screenshot, README или environment variables клиента. Убедитесь, что разворачивается HTTPS. Сверьте содержимое git status перед push. Используйте только синтетические данные; перенос реальных банковских данных требует согласований, модели доступа, правового и организационного анализа.

Отсутствие реальных персональных данных в генераторе не дает разрешения отправлять произвольные пользовательские секреты модели. Не вводите их в чат.

# Правила для AI-агентов разработки

Перед изменением прочитайте SPEC.md, README.md и docs/DECISIONS.md.

1. Сначала уточните критерий приемки и контракт, затем пишите реализацию и тест.
2. Не обходите MCP для чтения портфельных данных в API или агенте. Единственный write-path — bootstrap/CLI генератора.
3. Не заменяйте настоящий межпроцессный MCP обычной Python-функцией или имитацией журналов.
4. Не выдавайте DEMO за LLM. Ошибки настоящей модели должны оставаться видимыми.
5. Деньги — копейки INTEGER в БД, RUB на выходе; доли 0..1; изменения в п.п. Пустые знаменатели -> null.
6. Не называйте NPL90 proxy регуляторным NPL, toy EL — IFRS9 ECL, what-if — прогнозом, атрибуцию — причинностью.
7. Только параметризованный SQL. Названия колонок — из allowlist. Нет пользовательского кода, файлов, URL или shell в инструментах.
8. Не добавляйте реальные клиентские данные, персональные признаки, ключи и токены в репозиторий, prompt, логи или screenshots.
9. При добавлении инструмента обновите реестр, тесты, экспорт схем и документацию. Поддерживайте extra=forbid.
10. Ответы модели вставляйте через textContent / текстовые DOM-узлы, не через innerHTML.
11. Запускайте pytest, compileall и smoke. Не записывайте в README успех неисполненных live/CI/deploy-проверок.
12. Не придумывайте историю коммитов, отзывы пользователей, экономию времени, метрики качества LLM и публичные URL.

Команды:
```bash
python -m pytest -q
python -m compileall -q app scripts
python -m scripts.smoke
```

При изменении статистики генератора пересоберите встроенные данные презентации и скриншоты. При работе с реальным провайдером сначала получите разрешение владельца ключа на расходы и передачу данных.
